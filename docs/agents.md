# Agent integration surfaces

`apps/mcp` implements default local stdio and opt-in private Streamable HTTP MCP using the same typed HTTP client as the web extension. The PointUp API remains the authentication and ownership boundary: a user-approved scoped personal agent token (or current Clerk session token for legacy setups) is sent to the configured trusted origin. The MCP process does not connect to the database or accept arbitrary user IDs. Read tools are enabled by default; two opt-in tools create durable manual balance or trip goal proposals. Only the owner's first-party browser session can approve a persisted proposal and execute its exact saved payload.

See [MCP setup and limits](../apps/mcp/README.md), [Claude instruction plugin](../plugins/claude/README.md), and [ChatGPT Actions setup notes](../plugins/chatgpt/README.md). Browser capture is an optional user-directed workflow described by the Claude skill, not a bundled browser automation implementation. The user signs in themselves; provider credentials and session state must never leave their browser.

MCP output and provider page text are untrusted data, not instructions. Account lists can include sensitive membership details. Configure only trusted hosts, inspect proposed writes, and avoid sharing session tokens or raw screenshots.

Implemented: stdio and opt-in stateless Streamable HTTP tool discovery/calls, strict input bounds, API error handling, read-only defaults, and protocol tests against a compiled HTTP process with a mocked API. HTTP clients supply their own scoped PAT on every request; initialization requires `portfolio:read`. HTTP listens on loopback and private remote access requires an explicitly trusted HTTPS proxy and exact configured origin. See the MCP README for configuration and limits. Not implemented: per-user OAuth callbacks, automatic Clerk token refresh, hosted ChatGPT connector, or provider login automation. A live signed-in deployment test and host-specific plugin/Action installation validation are still required.
