# Sync feedback and explicit consent duration

Individual web sync used to return no feedback for an expired session or a domain failure. Bulk sync discarded the actual per-account `SyncOutcome[]`, making partial failures appear successful. Shared forms now show bounded domain guidance, successful balance confirmation, or actual updated/total/failed counts. Demo and configured API labels retain their existing qualification; unsupported accounts still offer manual entry and consented capture.

The server session supplies ownership. Provider messages, credential references and diagnostic bodies never enter returned feedback. The web adapter recognizes genuine domain errors across development module reloads. If the bulk core cannot return complete outcomes, the adapter never invents counts: a genuine domain rejection includes an unknown-partial-update warning; unexpected faults propagate to the existing error boundary. Owner cache invalidation already runs in the container's finally wrapper; page revalidation now also runs after attempted sync because another worker may have committed. This provides no rollback or automatic retry guarantee.

The web consent form formerly converted blank, zero, malformed and missing Days values into an actual 30-day grant. It now requires an explicit finite integer from 1 through 90 before invoking the use case, and the input has required/step constraints. Existing owner and foreign grants are preserved on invalid input. Core/API optional-duration defaults remain unchanged.

Mixed-generation error cases retain actual use cases across module resets.
