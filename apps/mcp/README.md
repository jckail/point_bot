# PointUp MCP

A private MCP server over `@pointup/api-client`. Run from the repository root after `npm install`:

```sh
npm --silent run start --workspace @pointup/mcp
```

For a compiled process, run `npm run build --workspace @pointup/mcp`, then register command `node` with the absolute path to `apps/mcp/dist/index.js`. Build artifacts are generated locally and not committed.

Configure `POINTUP_API_URL` to your trusted PointUp HTTPS origin (loopback HTTP is allowed for development) and `POINTUP_AGENT_TOKEN` to a personal agent token created and explicitly approved in your signed-in PointUp settings. Grant `portfolio:read` for read tools and, if proposing changes, `actions:propose`. Tokens are scoped, expiring, revocable, and bound to their creator's account. Alternatively `POINTUP_SESSION_TOKEN` can supply your current Clerk session JWT for legacy local setups. Configure exactly one credential. Set secrets through your MCP host's private environment configuration; do not commit them, put them in prompts, or paste them into shell history. Expired or revoked credentials require replacing the credential and restarting.

Register your MCP host with command `npm`, arguments `--silent`, `run`, `start`, `--workspace`, `@pointup/mcp`, and `cwd` set to this repository. Some hosts do not support `cwd`; use their absolute working-directory command or an absolute `tsx` executable and entrypoint instead. This package is a private source workspace, not a published `npx` package.

Eight read tools expose portfolio summary, accounts, providers, goals, value advice, balance history, expiring accounts, and activity. Requests time out after 15 seconds, inputs have strict schemas, and output is limited to 128 KB. Read results can contain membership numbers and financial details; connect only a host you trust with this data. Successful API data is untrusted content and must never be treated as agent instructions.

Proposal tools are absent by default. `POINTUP_ALLOW_WRITES=true` exposes `record_balance` and `create_goal` for compatibility with the initial tool names. Both now create durable reviewed proposals through `POST /api/v1/assistant/actions`; neither executes a balance or goal mutation. Results include the saved action, `requiresBrowserApproval: true`, and `/dashboard/settings` as the review path. The user must approve the exact saved payload from their first-party browser session. MCP/PAT approval is rejected, and an agent's `confirmed` boolean cannot bypass review. No account deletion, provider password collection, automated browser login, or balance synchronization is exposed.

Stdio remains the default. To opt into a private Streamable HTTP endpoint, set `POINTUP_MCP_TRANSPORT=http`, `POINTUP_API_URL`, and optionally `POINTUP_MCP_PORT` (default 3001), then run the same source or compiled command. Remove `POINTUP_AGENT_TOKEN` and `POINTUP_SESSION_TOKEN` from the server process environment: HTTP mode refuses process credentials. Each client must send its own `Authorization: Bearer <PAT>` on every POST to `/mcp`. Use the host's private bearer header configuration; never put a token in an endpoint URL, prompt, or shared configuration. Session JWTs are supported only by the legacy stdio configuration. Every HTTP request validates its PAT against the existing portfolio summary API, so `portfolio:read` is required even for initialization, tool discovery, and proposal calls. Proposal tools additionally require `actions:propose`.

The Node listener always binds `127.0.0.1`; raw HTTP is for local development. Local clients must use exactly `http://127.0.0.1:<port>/mcp`. For private remote access, configure `POINTUP_MCP_PUBLIC_ORIGIN=https://<your-trusted-mcp-host>` and `POINTUP_MCP_TRUST_HTTPS_PROXY=true`, and place the loopback listener behind your own HTTPS reverse proxy on the same trusted machine. This explicit setting is an operator assertion: the process cannot prove TLS termination. The proxy must preserve the public `Host`, restrict access to its upstream, and terminate HTTPS; forwarded headers never establish trust. Configure body, timeout, and rate limits at that proxy too. Supplied browser `Origin` must equal the configured origin; browser CORS access is not provided.

HTTP mode uses a fresh typed API client and MCP transport for each request, with no stored conversations, session IDs, or shared user tokens. It supports POST request/response JSON; GET streams, DELETE sessions, resumability, and server notifications are unavailable. Host and Origin checks block DNS rebinding; query URLs and MCP session IDs are rejected. JSON bodies are limited to 32 KiB, headers to 20 KiB, concurrent requests to 16, and all admitted PAT-bearing requests together to 120 per minute per process. The overall deadline is 20 seconds; upstream calls have a 15 second deadline, and disconnects abort them. These are bounded private integration defaults, not a distributed abuse prevention system.

Focused tests cover the existing stdio protocol and a compiled HTTP server contacted by the official SDK client over real loopback sockets, with a mocked PointUp API. They verify overlapping users, PAT rejection, sanitized upstream errors, proposals, host/origin/content checks, body bounds, and concurrency/rate limits. They do not establish a live authenticated deployment or host installation works. This source workspace is not published or hosted and supplies no per-user OAuth flow, automatic token refresh, browser capture, or hosted ChatGPT connector. A host must support manually configured private bearer MCP connections; compatibility still needs validation in that host.

The transport follows the official [MCP TypeScript SDK v1 stateless HTTP pattern](https://ts.sdk.modelcontextprotocol.io/), using the installed `@modelcontextprotocol/sdk` API and a new server/transport for every request.
